# 实施计划与验收

## 当前状态

本仓库已建立需求与实施跟踪入口，运行程序、认证集成、部署入口和内容库均待实现。详见 [任务 #1](https://github.com/maxwelles666/ask/issues/1)。

## 建议结构

候选技术组合为 Python 调度程序、SQLite 存储和轻量网页。先用普通文件保存提示模板；需要复用到交互式代理时再整理为 skill。

数据流：资料采集 → 去重 → 问题队列 → 受限生成 → 证据校验 → 成品库 → 阅读页面。

部署配置、账户信息和运行数据独立于源代码。公开仓库不承载实例私有交接信息。

## 阶段一：离线基础

- 定义资料、论断、卡片、专题、任务和阅读状态的数据结构。
- 实现数据保存、主题索引、收藏、已读和静态内容阅读。
- 使用明确标记的示例内容验证布局；不得将示例伪装成检索结果。

验收：关闭全部模型连接后仍可浏览、收藏和标记已读；重复保存不会产生重复卡片。

## 阶段二：资料与内容

- 接入选定的原始资料来源，遵守其访问与引用条件。
- 实现内容指纹、来源时间戳、证据片段及论断关联。
- 加入结构检查、重复检测、失效链接与证据不足状态。
- 模型复核可帮助发现问题，但不能代替来源核验。

验收：抽查每个关键论断都能定位到实际读取的证据；无证据的题目进入待查队列。

## 阶段三：认证与用量控制

- 从当前官方能力及实例所有者的私有配置选择接入方式。
- 如采用订阅应用授权，验证真实的应用注册、授权范围、限额档位和超限行为；按实际可用模型列表选择模型。
- 不假定独立目录、进程或服务器会得到独立额度。
- 对授权撤销、额度耗尽、限额无法验证和提供方不可用分别处理。
- 调度器在每个任务前检查条件；禁止无限重试和隐式计费渠道切换。

验收：使用模拟错误验证所有停止路径；真实调用仅在实例配置与授权完成后小规模进行。记录实际观察结果，不能将设计值当作服务保证。

## 阶段四：部署与运行

- 选择独立的进程、数据目录、端口和部署入口，避免占用其他项目的配置。
- 核实执行器的仓库归属与访问范围；已有执行器不能默认跨仓库调用。
- 普通代码检查使用不含生产凭据的环境。公开 PR 或其他不可信输入不能直接触发持有账户凭据的自托管执行器。
- 生成进程默认关闭；配置完成后验证启动、暂停、恢复、备份和重启行为。
- 完成小规模试运行，依据质量和实际用量调整产量与库存。

验收：后台生成可持续恢复，读取成品不依赖模型在线；达到库存阈值后暂停；失败重试有界；凭据不出现在仓库、构建产物或日志中。
