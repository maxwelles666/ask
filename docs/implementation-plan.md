# 实施与验收

## 当前方向

用户要求服务器上的纯文本系统知识，明确拒绝随机卡片和网页。当前入口是 `scripts/knowledge.py`，主题与前置关系保存在 `config/knowledge-plan.json`。先前卡片试跑已停止，不再继续界面开发。

## 当前实现

- 校验章节顺序和依赖；依赖未完成时不生成后续章。
- 每章带入完整目录、已经写出的正文摘录和选定原始资料，形成连贯论述。
- 生成各章文本、合订 `knowledge.txt`、目录 `index.txt` 和进度 `status.txt`。
- 已完成正文立即可读并保留；相同计划再次启动会跳过已完成章节。
- 默认预演不调用模型；显式启用才经已登录订阅通道生成。
- 一次运行有时间、调用次数和额度观测停止条件；没有付费 API 回退。
- 状态文件只报告实际进度和更新时间，不将残留进程号当成仍在工作。

## 验证与局限

基础停止、重试、引用、额度窗口变化和时间抖动等行为十五项测试通过。纯文本入口的依赖顺序、预演零调用、跳过成品、必须收到完成事件、状态更新与用量字段过滤已做离线模拟检查。私有服务器已启动有限章节生成，最终状态以实例的 `status.txt` 和运行记录为准。

当前用量控制属于观测后停止，不是提供方硬限额。章节提示包含证据和上下文，但并未实现自动专业事实审核。首轮主要验收内容是否连贯、概念是否准确、相关问题是否成体系，再决定产量与长期调度。

## 开源调查

[STORM](https://github.com/stanford-oval/storm) 已有多视角追问、大纲组织和有引用的全文生成；[GPT Researcher](https://github.com/assafelovic/gpt-researcher) 已有无界面的研究报告接口。两者均需配置其模型与检索接入，不能直接假定使用现有订阅。本轮借鉴 STORM 的组织方法，另加学习前置依赖；没有声称运行或安装这两个框架。

## 后续必要工作

先抽查本轮连续正文，修正事实错误、跳跃和重复。随后将知识目录、未解问题和前置关系持久化推进；只有在用量限制与内容质量均满足要求后，才启用长期后台生成。无需为普通阅读增加模型调用或界面服务。
